# Built during Monad Metropolis

Dated log of the work done in this repository during the hackathon window
(2026-09-01 → 2026-10-13). Pre-existing work is described in `PRIOR_WORK.md`.

| Date (UTC) | Work |
|---|---|
| 2026-10-09 | Created the Monad repository; research on the Metropolis rules, judges, competitors and Monad's x402 / ERC-8004 stack (`docs/MONAD-CONTEXT.md`); phase-by-phase Monad build plan (`docs/MONAD-PLAN.md`); prior-work and AI-tooling disclosure (`PRIOR_WORK.md`). |
| 2026-10-09 | **Phase 1 — contracts on Monad.** Ported the service registry and PolicyVault (UUPS) to Monad: Hardhat networks for Monad mainnet (143) and testnet (10143) with Monadscan verification; dropped the Avalanche-only ICM contracts and non-upgradeable duplicates; registry now only accepts an ERC-8004 `agentId` the caller owns or is approved for (new `NotAgentOwner` check + tests); deploy scripts default to Monad USDC and the canonical ERC-8004 IdentityRegistry, refuse an identity registry without code, and default the registration fee to 0; new generic preflight / postcheck / verify scripts; fixed the ownership-transfer script (PolicyVault ownership is single-step); re-pointed the full registry and vault test suites at the proxies (84 tests); solcjs fallback for offline compilation. |
| 2026-10-09 | **Phase 1 — Monad network config.** New `@chainpeavax/sdk` networks module: the single source of truth for Monad chain ids, CAIP-2 ids, RPCs (env-overridable), Circle USDC + EIP-712 domain, canonical ERC-8004 registries and explorers (11 tests). Monorepo workspace skeleton and Monad `.env.example`. |
| 2026-10-09 | **Phase 2 — x402 v2 facilitator for Monad.** Read the x402 v2 API and wrote `docs/X402-V2-NOTES.md` (wire format: `PAYMENT-REQUIRED` / `PAYMENT-SIGNATURE` / `PAYMENT-RESPONSE`, CAIP-2 networks, `amount` replaces `maxAmountRequired`). Ported the facilitator to `@x402/core` + `@x402/evm` v2 for `eip155:143` / `eip155:10143`: no longer an open gas relay (only USDC `exact` payments above a minimum, to registered or allow-listed payTo, whose signed offer matches the requirements); settlements serialized through a nonce manager; `trust proxy` set so rate limits are per client; MON-denominated low-gas alarm that respects Monad's 10 MON reserve; fixed the legacy test/behaviour mismatch by rewriting the HTTP tests (29 tests). |
| 2026-10-09 | **Phase 2 — SDK on x402 v2.** Ported the SDK payment client to `@x402/*` v2 (`PAYMENT-REQUIRED` / `PAYMENT-SIGNATURE` / `PAYMENT-RESPONSE`). New `payment.ts` runs the 402 loop itself and only signs an offer that is `exact`, on our CAIP-2 network, in that network's USDC (a server can no longer make the client sign for another token), and within `maxPerCall`; it returns the settlement tx hash and payTo that payment-backed reputation needs. Registry / reputation / PolicyVault clients retargeted to Monad; `Balances.avax` → `mon`; default network is testnet. Tested against a real x402 v2 resource server (express middleware + stub facilitator): 40 tests. |
| 2026-10-09 | **Phase 2 — provider proxy + CLI on x402 v2.** Ported the payment proxy to `@x402/express` v2: prices are explicit Monad-USDC amounts (never a library default asset), catch-all route gates every path, the provider's ERC-8004 agent id is advertised via `X-CHAINPE-AGENT-ID` and each offer's `extra`, and x402 headers are stripped before the request reaches the backend (the legacy proxy forwarded them). New SDK `RegistryWriter` (approve fee → register/update/deregister). Rewrote the CLI on the SDK: `init`, `start`, `register`, `deregister`, `status`, `fetch`, `discover`; keys only via `CHAINPE_PRIVATE_KEY`. End-to-end test backend → proxy → SDK payment (8 tests). Dropped the in-process facilitator and browser wallet-connect flow (run `services/chainpe-facilitator` instead). |
| 2026-10-09 | **Phase 2 — real settlement verified on a local chain.** New integration test: Hardhat node + MockUSDC (now with the same EIP-712 domain as Monad USDC) + the production facilitator code + an x402 v2 client. A signed payment verifies, settles on-chain (USDC moves payer → seller, facilitator pays gas), a replayed authorization is refused, 3 concurrent settlements get distinct txs with no nonce collisions, and an unregistered payTo is refused before any gas is spent. |
| 2026-10-09 | **Phase 2 — live Monad checks (read-only, no funds).** With network access opened: confirmed chain ids 143 / 10143, that Monad USDC and the canonical ERC-8004 Identity/Reputation registries have contract code on both networks, that Monad's public facilitator advertises `exact` on both, and — with a new `e2e/facilitator-probe.mjs` using a random throwaway signer — that it accepts a ChainPe-signed x402 v2 payment (answers `insufficient_funds` for the empty wallet). |
| 2026-10-09 | **Phase 3 — MCP wallet on Monad.** Ported `chainpe-wallet-mcp` to Monad and x402 v2: `x402_fetch` and `pay` no longer carry their own x402 flow but go through the SDK's `paidFetch`, so an offer is only signed if it is `exact`, on the wallet's Monad network, in Monad USDC, and within min(per-call cap, remaining daily budget); paid calls are serialized so concurrent calls cannot overspend. `transfer_avax` → `transfer_mon` (tight gas limits, reserve warning); `check_balance` returns MON + USDC; `request_funding` links the Monad MON faucet and Circle's USDC faucet; the budget now persists to `~/.chainpe/spending.json` (bigint atomic USDC, survives restarts, resets at UTC midnight); `search_bazaar` uses the indexer API when `CHAINPE_INDEXER_URL` is set, else the on-chain registry via the SDK; all network constants come from the SDK; manifest/README for Monad. 49 tests, including a real x402 v2 server driven through an MCP client (over-cap, non-USDC and wrong-network offers refused; budget survives a restart). Root build now builds the SDK first so a fresh clone builds. |
